# Give Me Some Credit — EDA Statistical Test Report

Generated by running `scripts` against `cs-training.csv` (150,000 rows) and `cs-test.csv`
(101,503 rows, unlabeled) from the cached KaggleHub competition data. All tests were run
with `scipy.stats`; significance threshold used throughout: **α = 0.01**.

## 1. Duplicate rows

| Check | Count |
|---|---|
| Fully duplicate rows (all 11 columns identical) | 609 |
| Duplicate rows ignoring the target column | 646 |

**Verdict:** Real data quality issue. 609 rows (0.4%) are exact duplicates, and 37 more
share every feature but disagree on the label — i.e. the same borrower profile appears
once as delinquent and once as not. These should be deduplicated (or at minimum flagged)
before modeling, since duplicates can leak between train/validation splits and inflate
apparent performance.

## 2. Invalid / suspicious values

| Check | Count | % of train |
|---|---|---|
| `age == 0` | 1 | <0.01% |
| `age < 18` | 1 | <0.01% |
| `NumberOfTime30-59DaysPastDueNotWorse` ∈ {96, 98} | 269 | 0.18% |
| `NumberOfTimes90DaysLate` ∈ {96, 98} | 269 | 0.18% |
| `NumberOfTime60-89DaysPastDueNotWorse` ∈ {96, 98} | 269 | 0.18% |
| `RevolvingUtilizationOfUnsecuredLines > 1` | 3,321 | 2.2% |
| `RevolvingUtilizationOfUnsecuredLines > 10` | 241 | 0.16% |
| `DebtRatio > 1` | 35,137 | 23.4% |
| `DebtRatio > 1` **and** `MonthlyIncome` missing | 27,904 | 18.6% |
| `MonthlyIncome == 0` | 1,634 | 1.1% |

**Verdict:**
- The single `age == 0` row is a data entry error (impossible value), not a real minor.
- The 96/98 codes in the three delinquency-count columns hit the *exact same 269 rows*
  in all three columns — this is a sentinel/placeholder value (not a real count of "96
  or 98 times late"), consistent with known issues in this Kaggle dataset. These rows
  should be treated as a separate missing/invalid category, not as extreme numeric
  values.
- `RevolvingUtilizationOfUnsecuredLines` is defined as a ratio and should theoretically
  sit in `[0, ~1-2]`; values above 10 (up to 50,708 in the full describe()) are
  data errors or unit mistakes.
- `DebtRatio > 1` for 23% of rows is unusually high for a genuine debt-to-income ratio,
  **and 79% of those rows also have missing `MonthlyIncome`**. This strongly suggests
  that when `MonthlyIncome` is not reported, `DebtRatio` is not actually a ratio for
  those rows but a raw dollar figure (e.g. total debt payments) — confirmed below in the
  missingness test, where the median `DebtRatio` in the "income missing" group (1,159) is
  over 3,000× the median in the "income present" group (0.30). Any modeling pipeline
  should treat `DebtRatio` differently (or add a `MonthlyIncome`-missing indicator)
  rather than feeding it in as-is.

## 3. Is missingness random? (MonthlyIncome, NumberOfDependents)

For each column with missing values, every other numeric feature was compared between
the "missing" and "not missing" groups with a two-sided Mann-Whitney U test. If
missingness were purely random (MCAR), none of these should be significant.

**Result: missingness is *not* random for either column.** Out of 9 other features
tested against each, only `NumberOfTimes90DaysLate` failed to reach significance (both
times) — every other feature differed significantly (p < 0.01, most at p < 1e-20)
between the missing and non-missing groups.

Most notable differences (`MonthlyIncome` missing vs. present):

| Feature | Median (income missing) | Median (income present) | p-value |
|---|---|---|---|
| `DebtRatio` | 1,159.0 | 0.296 | ~0 |
| `age` | 57 | 51 | ~0 |
| `NumberOfOpenCreditLinesAndLoans` | 6 | 8 | ~0 |
| `RevolvingUtilizationOfUnsecuredLines` | 0.082 | 0.177 | ~1e-281 |

The same pattern (older, lower utilization, fewer open lines, inflated `DebtRatio`)
holds for `NumberOfDependents` missingness.

**Verdict:** Both missingness patterns are **MAR (missing at random, conditional on
observed covariates)**, not MCAR. Mean/median imputation ignoring this structure will
distort relationships; a missingness indicator flag (already common practice for this
dataset) or model-based imputation conditioned on the correlated features above is
more appropriate than naive imputation.

**Additional finding — the two missingness patterns are nested, not independent.**
Every single row missing `NumberOfDependents` (3,828 of them, after deduplication) is
*also* missing `MonthlyIncome` — a 100% overlap. The reverse isn't true: only 13% of
the 29,221 rows missing `MonthlyIncome` are also missing `NumberOfDependents`. This
points to a single underlying cause (an "income section" of the original application
left blank) that sometimes takes both fields with it and sometimes only
`MonthlyIncome` — worth encoding as one shared `income_section_missing` flag rather
than two independent per-column indicators.

## 4. Train vs. test distributional shift (Kolmogorov–Smirnov)

Ran a two-sample KS test per shared feature (excludes the target, which is 100% missing
in `cs-test.csv` since it's the Kaggle scoring set).

**Result: no significant shift on any of the 10 features** (all p-values ≥ 0.29, all KS
statistics < 0.0044). Train and test look like they were drawn from the same underlying
distribution.

**Verdict:** Good news for generalization — no covariate shift correction is needed
between train and test.

## 5. Class imbalance

| | % of rows |
|---|---|
| Not delinquent (0) | 93.32% |
| Delinquent (1) | 6.68% |

Imbalance ratio ≈ **14:1**. Confirms this needs `class_weight`, resampling (SMOTE/
undersampling), or threshold tuning at modeling time, and that plain accuracy is not a
usable evaluation metric (AUC/PR-AUC/recall-at-precision are appropriate).

## 6. Feature–target associations

Computed both a point-biserial correlation (Pearson-based, sensitive to outliers) and a
Mann-Whitney U test (rank-based, robust to outliers) between each feature and
`SeriousDlqin2yrs`, using a copy of the data with the 96/98 sentinel codes set to NaN.

| Feature | Point-biserial r | MWU significant? |
|---|---|---|
| `NumberOfTimes90DaysLate` | **0.315** | yes |
| `NumberOfTime30-59DaysPastDueNotWorse` | **0.275** | yes |
| `NumberOfTime60-89DaysPastDueNotWorse` | **0.268** | yes |
| `age` | -0.115 | yes |
| `NumberOfOpenCreditLinesAndLoans` | -0.030 | yes |
| `MonthlyIncome` | -0.020 | yes |
| `NumberOfDependents` | 0.046 | yes |
| `DebtRatio` | -0.008 | yes |
| `NumberRealEstateLoansOrLines` | -0.007 | yes |
| `RevolvingUtilizationOfUnsecuredLines` | -0.002 (not significant, p=0.49) | **yes** (p≈0) |

**Notable finding:** `RevolvingUtilizationOfUnsecuredLines` shows essentially zero
*linear* correlation with the target, but the Mann–Whitney test finds a highly
significant difference, and the raw group medians are dramatic (0.84 for delinquent
borrowers vs. 0.13 for non-delinquent). This is a textbook case of **outliers destroying
a Pearson-family correlation**: the handful of rows with utilization in the thousands
(vs. a theoretical max near 1-2) dominate the linear correlation calculation while
contributing nothing to the rank-based test. This variable is genuinely predictive but
needs outlier capping/transformation (e.g. clip at a reasonable ceiling or log-transform)
before it will show up properly in linear models or correlation-based feature selection.

The delinquency-history features (30-59, 60-89, 90+ days late) are, unsurprisingly, the
strongest predictors by a wide margin.

## 7. Multicollinearity

- Spearman correlation matrix: strongest pairwise correlation is
  `NumberOfOpenCreditLinesAndLoans` ↔ `NumberRealEstateLoansOrLines` at **0.473** — a
  moderate, unsurprising relationship (both reflect overall credit-line activity), not a
  redundancy concern.
- The three delinquency-count columns correlate with each other at 0.24–0.30 — related
  but each contributes distinct information, not redundant duplicates of one measure.
- **Variance Inflation Factors:** all features have VIF between 1.00 and 1.28 (rule of
  thumb: concern starts around 5, serious problem above 10).

**Verdict:** No meaningful multicollinearity. Feature set can be used as-is for linear
models without dimensionality reduction on collinearity grounds.

## Summary of actionable findings

1. Drop or flag the 609 exact duplicate rows (and investigate the 37 contradictory-label
   duplicates).
2. Treat `age == 0` as a missing/invalid value, not a real age.
3. Replace the 96/98 sentinel codes in the three delinquency-count columns with NaN (or a
   dedicated missing-indicator) rather than modeling them as counts of 96–98 late
   payments.
4. `DebtRatio` behaves differently when `MonthlyIncome` is missing — build a
   `MonthlyIncome`-missing flag and consider treating/capping `DebtRatio` separately
   for that subgroup.
5. Missingness in `MonthlyIncome`/`NumberOfDependents` is MAR, correlated with age, debt
   ratio, utilization, and credit-line count — condition any imputation on those
   features rather than using an unconditional mean/median fill.
6. `NumberOfDependents`-missing rows are a strict subset of `MonthlyIncome`-missing
   rows (100% vs. 13% overlap) — a single shared missingness flag likely captures the
   underlying cause better than two independent indicators.
7. No train/test distribution shift — safe to validate locally without extra shift
   correction.
8. Severe class imbalance (14:1) — use AUC/PR-AUC, class weighting, or resampling, not
   accuracy.
9. Cap/transform `RevolvingUtilizationOfUnsecuredLines` before relying on linear
   correlation for feature selection — it is predictive but outlier-masked.
10. No multicollinearity concerns (max VIF 1.28) — all features safe to keep for linear
    models.
